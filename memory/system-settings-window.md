**Что попросил пользователь 17.11.2026.** В File, в группе с Recipe Editor, пункт System Settings. Сначала окно пароля, пароль один и зашит в код: `ardis2027` (`PasswordForm.Password`), без config.ini. Потом окно отладки ПЛК. Connect/Disconnect и Start/Stop logging убраны из File и перенесены в это окно: пункты меню удаляются в рантайме `MainForm.MoveLinkAndLoggingToSystemSettings`, Designer не тронут. File теперь: Recipe Editor, System Settings, разделитель, Exit. Выбранные функции: связь со слейвами, сбросы, просмотр регистров (отдельным окном `RegisterViewerForm`, кнопка Registers...). Тесты выходов НЕ выбраны. Менять ПЛК разрешено. Пароль спрашивается при каждом открытии, если окно уже открыто — просто активируется (это моё допущение).

**Почему РРГ показывает `---`, а Connection Status «всё хорошо».** Слейв на COM-порту (`ModbusSlaveComPort`) после ошибки держит `xError` и прерывает связь, пока не дёрнуть `xReset` (сбрасывает ошибку) или `xAcknowledge`. У COM-слейвов НЕТ `xConfirmError`, он только у TCP-слейвов (PYRO_RXT, MW_GEN), проверено по документации CODESYS. Регулятор, который включился позже ПЛК, остаётся мёртвым навсегда. Connection Status этого не видит: при выключенном газе все каналы показывают одинаковое «Closed (subsystem disabled)», а `SlaveError` (`awHolding[96]`) там не выводится. Автоквитирование и строки в Connection Status пользователь отложил, вместо них сделано это окно.

**Как устроено.** `PLC210DebugClient` — отдельный сокет, работает только пока открыто одно из двух окон (счётчик пользователей Start/Stop), раз в 500 мс читает весь `awHolding[0..295]` тремя запросами и шлёт команды в 148, см. [[plc210-register-contract]]. Состояние строк берётся из уже работающих клиентов: MFC по биту `DiagSlaveErrorMask` в порядке ПЛК (имена устройств, а не газов, чтобы обойти нерешённую путаницу O2/N2 из [[ardis-cvdcore-open-work]]), PYRO_RXT/MW_GEN/TURBO_PUMP/Thyracont по своим клиентам, модули охлаждения выводятся из валидности каналов. Reconnect у PYRO_RXT и MW_GEN — существующие запросы (170 бит 0, 192 бит 3). Reset alarms = `SystemStatus.ResetFaults`, Reset chamber PID = `PLC210PidClient.RequestReset` (выход PID падает на нижний предел), Reinit gas regulators = код 20.

**В ПЛК добавить вручную:** `GVL_Debug`, `PRG_Debug` (вызывать в MainTask), правка `PRG_GasFlow` (uiReinitSeen + блок перед CASE).

**Перезагрузка контроллера (сделано 17.11.2026, не прошито).** Источник — FAQ ОВЕН «CODESYS V3.5 FAQ» v3.1, п. 13.3: BOOL привязывается к каналу **Reboot** узла **Watchdog** таргет-файла, по переднему фронту контроллер корректно перезагружается. SSH и правка CODESYSControl.cfg НЕ нужны. Код 30 в `awHolding[148]` → `PRG_Debug` даёт TP 2 с в `GVL_Debug.xDbgReboot`; пользователь привязывает его в дереве устройств. Кнопка Reboot PLC в группе Resets, двойное подтверждение. Веб-конфигуратор ПЛК210: root / owen по умолчанию; режим watchdog «Перезагрузка» во вкладке ПЛК/Настройки — это реакция на исключение, не то же самое.
